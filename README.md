# Оптимизация процесса обработки обращений в банке (Кейс Газпромбанка)

## О чём проект
Это проект по написанию бизнес-требований (BRD) для оптимизации работы с обращениями клиентов в банке. 
Заказчик (банк) столкнулся с проблемой: клиенты не понимают, на каком этапе находится их обращение, долго ждут ответа, а данные приходится вводить заново.

## Что сделано
1. **Исследование AS-IS:** описала текущий процесс, выявила "узкие места" (разрозненные каналы, нет трекинга, закрытие без обратной связи).
2. **Написание бизнес-требований:** сформулировала бизнес-цели, границы проекта, функциональные (FR) и нефункциональные (NFR) требования.
3. **Проектирование TO-BE:** разработала целевую модель процесса в нотации BPMN 2.0. Суть изменений: единая точка входа, автоматическая идентификация клиента по ЕСК, автозаполнение полей, маршрутизация и трекинг статуса.
4. **UI-прототипирование:** спроектировала макет формы подачи обращения (UI-форма), чтобы клиенту не приходилось вводить данные руками.
5. **CJM (Customer Journey Map):** проанализировала путь клиента и определила точки роста (пик негатива приходится на ожидание ответа).

## Материалы проекта
- `Оптимизация_процесса_обработки_обращений.md` — полный документ с требованиями и схемами.
- `Оптимизация_процесса_обработки_обращений.pdf` — презентация для защиты проекта.
- `images/` — схемы процессов AS-IS и TO-BE, макет UI-формы.

## Ключевые метрики эффективности (KPI)
- Рост удовлетворенности (CSAT) до 4,5 из 5.
- Снижение операционных затрат на 25%.
- Сокращение повторных обращений до 10%.

## Инструменты
